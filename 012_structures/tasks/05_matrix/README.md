# Матрица

Матрица `rows x cols` хранится в одном блоке памяти из кучи, а структура
держит её размеры и указатель на числа. Типы и функции лежат в `matrix.h`:

```c
struct matrix {
    size_t rows;
    size_t cols;
    double* data;
};

struct matrix matrix_create(size_t rows, size_t cols);
void matrix_free(struct matrix* m);
bool matrix_is_empty(const struct matrix* m);

struct matrix matrix_add(const struct matrix* a, const struct matrix* b);
struct matrix matrix_mul(const struct matrix* a, const struct matrix* b);
struct matrix matrix_transpose(const struct matrix* m);
```

`matrix_create`, `matrix_free` и `matrix_is_empty` уже написаны. Реализовать
в `matrix.c` сложение, умножение и транспонирование.

## Как матрица лежит в памяти

Двумерного массива здесь нет. Все `rows * cols` чисел лежат подряд, строка за
строкой:

```
| 1 2 3 |
| 4 5 6 |   ->   data: 1 2 3 4 5 6
```

Перед строкой `i` лежат `i` полных строк по `cols` чисел, это `i * cols`
элементов. Внутри строки нужно пройти ещё `j`. Отсюда формула:

```
элемент (i, j)  ->  data[i * cols + j]
```

Для примера выше элемент `(1, 2)`, то есть 6, лежит в `data[1 * 3 + 2] = data[5]`.

Во вводе числа тоже идут по строкам, поэтому `main` читает их прямо в `data`
подряд.

## Математика

### Сложение

Складывать можно только матрицы одного размера, каждый элемент со своим:

```
(A + B)(i, j) = A(i, j) + B(i, j)
```

Раз размеры совпадают, совпадает и раскладка в памяти: `k`-й элемент `a->data`
складывается с `k`-м элементом `b->data`. Хватает одного цикла по всем
`rows * cols` элементам, двойной не нужен.

### Умножение

Матрицу `A` размера `m x n` можно умножить на `B` размера `n x p`. Количество
столбцов `A` должно совпадать с количеством строк `B`, а результат получается
размера `m x p`:

```
C(i, j) = A(i, 0) * B(0, j) + A(i, 1) * B(1, j) + ... + A(i, n-1) * B(n-1, j)
```

Это скалярное произведение `i`-й строки `A` на `j`-й столбец `B` (задание
про геометрию). В раскладке по строкам:

```
A(i, k) = a->data[i * a->cols + k]
B(k, j) = b->data[k * b->cols + j]
```

Пример:

```
| 1 2 |   | 5 6 |   | 1*5 + 2*7   1*6 + 2*8 |   | 19 22 |
| 3 4 | * | 7 8 | = | 3*5 + 4*7   3*6 + 4*8 | = | 43 50 |
```

Что важно понимать:

- **`A * B` и `B * A` — разные вещи.** Для тех же матриц:

  ```
  A * B = | 19 22 |      B * A = | 23 34 |
          | 43 50 |              | 31 46 |
  ```

- `B * A` может иметь другой размер или вообще не существовать:
  `2x3 * 3x2` даёт `2x2`, а `3x2 * 2x3` даёт `3x3`.
- Строка на столбец (`1xn * nx1`) даёт матрицу `1x1` — обычное скалярное
  произведение. Столбец на строку (`nx1 * 1xn`) даёт целую матрицу `nxn`.
- Единичная матрица `I` (единицы на диагонали, остальное нули) ничего не
  меняет: `A * I = I * A = A`.
- Для квадратных матриц `n x n` умножение стоит `n^3` умножений чисел.

### Транспонирование

Строки становятся столбцами: элемент `(i, j)` переезжает в `(j, i)`, а размер
`rows x cols` меняется на `cols x rows`:

```
t->data[j * t->cols + i] = m->data[i * m->cols + j]     (t->cols == m->rows)
```

У неквадратной матрицы при транспонировании меняется вся раскладка в памяти,
и сделать это на месте — отдельная непростая задача. Поэтому функция строит
новую матрицу.

Полезные проверки: `(A^T)^T = A` и `(A * B)^T = B^T * A^T`.

## Кто освобождает память

- Каждая функция, вернувшая непустую матрицу, выделила под неё память.
  Освобождает её вызывающий: `matrix_free`, ровно один раз на матрицу.
- `matrix_free` сбрасывает структуру в `{0, 0, NULL}`, поэтому повторный вызов
  безопасен: `free(NULL)` ничего не делает.
- Копия структуры `struct matrix c = a;` — это второй указатель на те же числа,
  как в `02_params/5_shallow_copy.c`. Освобождать можно только одну из копий.
- Функции принимают указатели, поэтому результат одной нельзя сразу передать в
  другую: `matrix_mul(&matrix_add(&a, &b), &c)` не соберётся. Это к лучшему:
  промежуточная матрица без имени утекла бы.
- `const struct matrix*` защищает поля `rows`, `cols` и сам указатель `data`,
  но не числа, на которые он указывает: `a->data[0] = 0` скомпилируется. Входные
  матрицы менять нельзя, следить за этим придётся самим.

## Пустая матрица

Как в задании про прямоугольники, «результата нет» — это особое значение
`{0, 0, NULL}`. Функция возвращает его, если размеры не подходят или если не
хватило памяти. По одному такому значению причину не различить, для этого
понадобился бы отдельный код ошибки.

## Требования

- Размеры проверять до выделения памяти.
- Результат создавать через `matrix_create`: память уже заполнена нулями.
  Если она вернула пустую матрицу, вернуть пустую.
- Индексы считать только по формуле `i * cols + j`.
- Входные матрицы не менять.
- Прогнать решение под `valgrind`: утечек быть не должно.

## Сборка

```sh
gcc -Wall -Wextra -std=c17 main.c matrix.c -o app
./app < basic.txt
valgrind -q --leak-check=full ./app < basic.txt
```

## Заметка про скорость

Во внутреннем цикле умножения `b->data[k * b->cols + j]` при каждом шаге `k`
прыгает на целую строку вперёд: идём по столбцу. Для больших матриц это заметно
медленнее, чем идти по строке подряд, потому что процессор подгружает память
кусками. Если поменять местами циклы по `j` и `k`, оба внутренних обращения
пойдут по памяти подряд.
