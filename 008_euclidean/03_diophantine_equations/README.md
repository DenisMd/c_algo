# Линейные диофантовы уравнения

Диофантово уравнение — уравнение, у которого ищутся **целые** решения. Здесь
рассматривается линейное уравнение с двумя неизвестными:

```
a * x + b * y = c
```

где `a, b, c` заданы, а `x, y` — целые. Ключевой факт (следствие соотношения
Безу):

> Целые решения существуют тогда и только тогда, когда `gcd(a, b)` делит `c`.

Реализация одна — функция `solve_diophantine`. Она **переиспользует** расширенный
алгоритм Евклида из прошлого урока: вызывает `gcd_ext`, получает `g = gcd(a, b)`
и коэффициенты Безу `x0, y0` (где `a*x0 + b*y0 = g`), а затем домножает их на
`c/g`. Возвращает `1` и записывает `x, y`, если решение есть, иначе `0`.


Вывод `make run` для входа `6 15 9` (решение есть, `gcd(6,15)=3` делит `9`):

```

```

Для входа `6 15 10` (нет решения, `3` не делит `10`):

```

```

## Как это устроено

### Переиспользование прошлого урока

Главная особенность урока — решение **вызывает `gcd_ext` из урока 02**, а не
пишет алгоритм Евклида заново. Собирается это так:

- `bin/app`   ← `obj/main.o` + `obj/algo.o` + `obj/gcd_ext.o`
- `bin/tests` ← `obj/test_algo.o` + `obj/algo.o` + `obj/gcd_ext.o` + `obj/testsuite.o`

`obj/gcd_ext.o` компилируется из `../02_gcd_extended/algo/solved_algo/algo.c` —
эталонной реализации расширенного алгоритма. Так урок работает независимо от
того, решён ли уже урок 02. Файл `algo/algo.c` подключает заголовок соседа
напрямую:

```c
#include "algo.h"                            // свой заголовок: solve_diophantine
#include "../../02_gcd_extended/algo/algo.h"  // прошлый урок: gcd_ext
```

Чтобы два заголовка с именем `algo.h` не конфликтовали, у здешнего своя защита
включения (`#ifndef DIOPHANTINE_H`), а у соседнего — `#ifndef ALGO_H`.

### Математика в двух шагах

1. `gcd_ext(a, b, &x0, &y0)` даёт `g` и частное решение `a*x0 + b*y0 = g`.
2. Если `c % g != 0` — целых решений нет (возвращаем `0`).
   Иначе домножаем на `c/g`: `x = x0*(c/g)`, `y = y0*(c/g)`.

Особый случай `a == b == 0`: уравнение вырождается в `0 == c` — решение есть
только при `c == 0` (тогда годится любая пара, берём `(0, 0)`).

Найденное решение — лишь **одно** из бесконечного семейства. Общее решение:

```
x = x0*(c/g) + k*(b/g)
y = y0*(c/g) − k*(a/g)      k — любое целое
```

Тест проверяет, что при `ok == 1` пара действительно удовлетворяет уравнению
`a*x + b*y == c`. Произведение `a*x` может не влезть в `long long`, поэтому
проверка считается в `__int128`.

### Переменные Makefile

- **`TESTSUITE`** — путь до общей библиотеки тестов (`../../utils/testsuite`).
- **`GCD_EXT_DIR` / `GCD_EXT_SRC` / `GCD_EXT_HDR`** — где лежит переиспользуемый
  `gcd_ext` из урока 02. По умолчанию берётся эталон (`solved_algo/algo.c`);
  если урок 02 уже решён, можно переключить `GCD_EXT_SRC` на его `algo/algo.c`.
- **`CFLAGS`** — флаги компилятора:
  - `-Wall -Wextra` — включить предупреждения;
  - `-g` — отладочная информация;
  - `-std=c11` — стандарт языка C11;
  - `-Ialgo -I$(TESTSUITE)` — где искать заголовки `#include "..."`.

Модуль `gcd_ext` компилируется отдельным правилом со своим `-I` (на папку algo
урока 02), чтобы его собственный `#include "algo.h"` нашёл нужный заголовок.

## Отладка через gdb

Флаг `-g` уже стоит в `CFLAGS`, поэтому оба бинарника собираются с отладочной
информацией — можно ставить точки останова по именам функций и номерам строк.

Если утилиты `gdb` нет:

```sh
sudo apt install gdb
```

### Пример: отладка тестов

```sh
make test           # сначала собрать bin/tests
gdb ./bin/tests     # запустить отладчик
```

Внутри gdb:

```gdb
(gdb) break solve_diophantine   # точка останова на входе в решатель
(gdb) run                       # запустить программу
(gdb) info args                 # аргументы: a, b, c и указатели x, y
(gdb) next                      # выполнить одну строку (не заходя в вызовы)
(gdb) print g                   # посмотреть найденный НОД
(gdb) print factor              # и множитель c/g
(gdb) continue                  # продолжить до следующей точки останова
(gdb) quit                      # выйти
```

Так как решатель **вызывает `gcd_ext` из прошлого урока**, в него можно зайти
командой `step` — gdb перейдёт прямо в исходник урока 02:

```gdb
(gdb) break solve_diophantine
(gdb) run
(gdb) step                      # шагнуть внутрь вызова gcd_ext(...)
(gdb) bt                        # backtrace: solve_diophantine -> gcd_ext
(gdb) finish                    # доработать gcd_ext и вернуться назад
```

Чтобы посмотреть, что записалось по указателям `x` и `y`, разыменуйте их:

```gdb
(gdb) print *x
(gdb) print *y
```

Точно так же отлаживается и сама программа — вместо `bin/tests` берётся `bin/app`
(она попросит ввести три числа после команды `run`):

```sh
make
gdb ./bin/app
```
