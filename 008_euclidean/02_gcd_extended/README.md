# Расширенный алгоритм Евклида

Обычный алгоритм находит `g = gcd(a, b)`. Расширенный вдобавок находит целые
коэффициенты `x` и `y`, для которых выполняется **соотношение Безу**:

```
a * x + b * y = g
```

Например, `gcd(12, 8) = 4`, и `12*1 + 8*(-1) = 4`, то есть `x = 1, y = -1`.

Идея та же, что в обычном алгоритме: тот же цикл делений, но параллельно с
остатками мы ведём коэффициенты при `a` и при `b` и обновляем их по той же
формуле. Есть две реализации — итеративная (`gcd_ext`) и рекурсивная
(`gcd_ext_rec`); НОД возвращается, `x` и `y` пишутся по указателям.

## Структура каталога

```
02_gcd_extended/
├── Makefile
├── algo/
│   └── algo.c, algo.h     — сам алгоритм (общий для программы и тестов)
├── exec/
│   └── main.c             — ввод чисел с клавиатуры и печать результата
├── tests/
│   └── test_algo.c        — тесты на общей библиотеке ../../utils/testsuite
├── obj/                   — объектные файлы .o (создаётся make, чистится clean)
└── bin/                   — готовые бинарники app и tests (создаётся make, чистится clean)
```

## Команды

| Команда      | Что делает                                    |
|--------------|-----------------------------------------------|
| `make`       | Собрать программу в `bin/app`                 |
| `make run`   | Собрать и запустить программу                 |
| `make test`  | Собрать и прогнать тесты                       |
| `make clean` | Удалить каталоги `obj/` и `bin/`              |

Если утилиты `make` нет:

```sh
sudo apt install make
```

## Примеры

```sh
make            # соберёт bin/app
make run        # запросит "Enter 2 integers:" и напечатает НОД и коэффициенты
make test       # прогонит проверки из tests/test_algo.c
make clean      # удалит всё сгенерированное
```

Вывод `make run` для входа `12 8`:

```
gcd(12, 8) = 4
12 * (1) + 8 * (-1) = 4
```

## Как это устроено

Сборка идёт в два шага: сначала каждый `.c` компилируется в объектный файл `.o`
в каталоге `obj/`, затем объектники линкуются в бинарник в `bin/`.

- `bin/app`   ← `obj/main.o` + `obj/algo.o`
- `bin/tests` ← `obj/test_algo.o` + `obj/algo.o` + `obj/testsuite.o`

Модуль `algo.o` собирается один раз и используется и программой, и тестами.
Каждое правило зависит от своих заголовков (`algo.h`, `testsuite.h`), поэтому при
изменении `.h` пересобирается только то, что от него зависит.

Тест проверяет не только сам НОД, но и **соотношение Безу** `a*x + b*y == g` —
именно оно ловит случай, когда `g` угадан верно, а коэффициенты `x, y` неверные.
Произведение `a*x` считается в `__int128`, чтобы не переполнить `long long` на
больших числах.

### Переменные Makefile

- **`TESTSUITE`** — путь до общей библиотеки тестов (`../../utils/testsuite`).
  Задан один раз, меняется в одном месте.
- **`CFLAGS`** — флаги компилятора:
  - `-Wall -Wextra` — включить предупреждения;
  - `-g` — отладочная информация;
  - `-std=c11` — стандарт языка C11;
  - `-Ialgo -I$(TESTSUITE)` — где искать заголовки `#include "..."`.

## Отладка через gdb

Флаг `-g` уже стоит в `CFLAGS`, поэтому оба бинарника собираются с отладочной
информацией — можно ставить точки останова по именам функций и номерам строк.

Если утилиты `gdb` нет:

```sh
sudo apt install gdb
```

### Пример: отладка тестов

```sh
make test           # сначала собрать bin/tests
gdb ./bin/tests     # запустить отладчик
```

Внутри gdb:

```gdb
(gdb) break gcd_ext        # точка останова на входе в функцию gcd_ext
(gdb) run                  # запустить программу
(gdb) info args            # показать аргументы: a, b и указатели x, y
(gdb) next                 # выполнить одну строку (не заходя в вызовы)
(gdb) print old_r          # заглянуть в остаток
(gdb) print old_s          # и в коэффициент при a
(gdb) continue             # продолжить до следующей точки останова
(gdb) quit                 # выйти
```

Чтобы посмотреть, что функция записала по указателям `x` и `y`, разыменуйте их:

```gdb
(gdb) print *x             # текущее значение коэффициента x
(gdb) print *y             # текущее значение коэффициента y
```

Полезно при отладке рекурсии `gcd_ext_rec`:

```gdb
(gdb) break gcd_ext_rec    # остановка на каждом рекурсивном вызове
(gdb) run
(gdb) bt                   # backtrace — вся цепочка вложенных вызовов
(gdb) info args            # a, b на текущем уровне рекурсии
(gdb) continue             # к следующему вызову gcd_ext_rec
```

Точку останова можно ставить и по номеру строки в конкретном файле:

```gdb
(gdb) break algo.c:10      # остановка на строке 10 файла algo.c
```

Точно так же отлаживается и сама программа — вместо `bin/tests` берётся `bin/app`
(она попросит ввести два числа после команды `run`):

```sh
make
gdb ./bin/app
```
