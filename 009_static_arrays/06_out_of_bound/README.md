# 06 — Выход за границу массива (out of bounds)

Обращение к `arr[i]` при `i < 0` или `i >= ARR_SIZE` — это **Undefined Behavior**.
«Работает» не значит «корректно»: программа может печатать мусор, тихо портить
чужие данные или падать — как повезёт с раскладкой памяти и флагами компилятора.

## Файлы

| файл | точка | что показывает |
|------|-------|----------------|
| `app_1.c` | 0 | недалеко за границей — **незаметно** (мусор, краха нет); далеко — **segfault** |
| `app_2.c` | 1 | записью за границу массива можно **закоррапить** соседний массив в памяти |
| `app_3.c` | 3 | типичная ошибка `i <= ARR_SIZE` (off-by-one) вместо `i < ARR_SIZE` |
| этот README | 2 | какие **санитайзеры** включать, чтобы ловить всё это |

## Обычная сборка (баг прячется)

```bash
gcc -Wall -Wextra -std=c11 app_1.c -o app_1 && ./app_1   # мусор, потом segfault
gcc -Wall -Wextra -std=c11 app_2.c -o app_2 && ./app_2   # соседний victim молча перезаписан
gcc -Wall -Wextra -std=c11 app_3.c -o app_3 && ./app_3   # *** stack smashing detected ***
```

Заметь: `-Wall -Wextra` тут **не помогают** — индекс вычисляется в рантайме,
компилятор его не видит. Нужны инструменты времени выполнения.

## Точка 2: санитайзеры

Собирай отладочные бинарники так (`-g` — чтобы были номера строк):

```bash
gcc -std=c11 -g -fsanitize=address,undefined -fno-omit-frame-pointer app_1.c -o app_1_san
./app_1_san
```

- **ASan** (`-fsanitize=address`) — ловит доступ за пределы *объекта* в памяти
  (стек, куча). На всех трёх примерах печатает `stack-buffer-overflow` с точной
  строкой — между соседними переменными на стеке ASan ставит «красную зону».
- **UBSan** (`-fsanitize=undefined`) — включает проверку границ массива по его
  *объявленному типу*. Ловит `index 8 out of bounds for type 'int [8]'`.

### Почему нужны ОБА

Они ловят разные классы ошибок и лишь частично пересекаются:

- ASan — про *память*: выход за объект, use-after-free, двойной free, утечки.
  Но если запись остаётся внутри одного объекта (например, за концом поля
  структуры, но в пределах самой структуры), красной зоны там нет — ASan промолчит.
- UBSan — про *язык*: индекс за объявленными границами массива, знаковое
  переполнение, сдвиги, разыменование NULL. Границу `int[8]` он проверяет по типу,
  даже когда физически рядом лежит валидная память.

Поэтому в учебных и отладочных сборках включай их вместе:
`-fsanitize=address,undefined`.

### Полезные флаги

```bash
# останавливаться на первой же ошибке UBSan с ненулевым кодом возврата
export UBSAN_OPTIONS=halt_on_error=1:print_stacktrace=1
# подробный отчёт ASan
export ASAN_OPTIONS=abort_on_error=1

# защита стекового canary есть и без ASan (обычно включена по умолчанию):
gcc -fstack-protector-strong ...
```

## Точка 3: правило против off-by-one

Валидные индексы массива из `N` элементов — это `0 .. N-1`.
В цикле по массиву всегда **строго меньше**:

```c
for (size_t i = 0; i < ARR_SIZE; i++)   // OK: i = 0..ARR_SIZE-1
for (size_t i = 0; i <= ARR_SIZE; i++)  // BUG: off-by-one, лишний arr[ARR_SIZE]
```
