# 07 — Отладка массивов в gdb

Как смотреть массивы под отладчиком. Программа [`app.c`](app.c) — обычный
`int`-массив, который заполняется в цикле, плюс функции `array_sum` / `array_max`.

## Сборка для отладки

Главное — флаги `-g` (символы отладки) и `-O0` (без оптимизаций, иначе
переменные «исчезают» и по коду не походить пошагово). Здесь берём `-g3`:
это добавляет ещё и информацию о `#define`, так что в gdb можно писать
`ARR_SIZE`, а не только число 8.

```bash
gcc -g3 -O0 -std=c11 -Wall -Wextra app.c -o app
gdb ./app
```

## Минимальный сценарий

```gdb
break main            # или:  b array_sum   /   b app.c:36
run                   # r — запустить до брейка
next                  # n — следующая строка (через вызовы)
step                  # s — зайти внутрь вызова
continue              # c — до следующего брейка
finish                # доработать текущую функцию и выйти
info locals           # все локальные переменные кадра
info args             # аргументы функции
bt                    # backtrace — стек вызовов
```

## Смотрим массив целиком

Для **статического** массива gdb знает его размер из типа `int[8]`:

```gdb
print arr              # {-3, -2, 1, 6, 13, 22, 33, 46}
p arr                  # p — сокращение от print
p/x arr                # в hex: {0xfffffffd, 0xfffffffe, 0x1, ...}
p/d arr                # десятичные   p/t — двоичные   p/c — как символы
```

## Отдельные элементы и срезы

```gdb
print arr[0]           # один элемент
print arr[2]@3         # СРЕЗ: 3 элемента начиная с arr[2] -> {1, 6, 13}
print arr[0]@ARR_SIZE  # весь массив через оператор @ (искусственный массив)
```

Оператор `@` — «показать N штук, начиная отсюда». Незаменим, когда gdb не знает
длину (см. ниже про указатели).

## Массив внутри функции — это указатель!

Параметр `long array_sum(const int arr[], ...)` на самом деле `const int*`.
Поэтому `print arr` покажет **адрес**, а не элементы. Длину gdb не знает — задаём
её вручную через `@`:

```gdb
b array_sum
run
print arr              # $1 = (const int *) 0x7fffffffe540   <- просто адрес
print *arr@size        # {-3, -2, 1, 6, 13, 22, 33, 46}      <- вот элементы
whatis arr             # type = const int *   (подтверждаем, что это указатель)
```

`*arr@size` = «разыменуй arr и покажи `size` элементов подряд».

Хочешь увидеть исходный массив как массив — поднимись в кадр `main`:

```gdb
up                     # перейти в вызывающий кадр (main)
print arr              # тут arr уже int[8] -> печатается целиком
down                   # вернуться обратно
```

## Наблюдение за изменением (watchpoint)

Удобно, чтобы поймать, КОГДА и ГДЕ меняется элемент:

```gdb
break main
run
watch arr[3]           # остановиться, когда изменится arr[3]
continue               # gdb сам встанет на изменении:
                       #   Old value = 0
                       #   New value = 6
```

## Менять значения на лету и авто-показ

```gdb
set var arr[0] = 999   # переписать элемент прямо в отладке
display arr            # печатать arr автоматически после каждого шага
display/x arr[3]       # авто-показ конкретного элемента в hex
undisplay 1            # убрать авто-показ №1
print sizeof(arr)/sizeof(arr[0])   # длина статического массива = 8
```

## Полезные настройки печати

```gdb
set print array on     # печатать массивы «столбиком», удобно для длинных
set print pretty on    # красивый отступ для вложенных структур
set print elements 200 # не обрезать длинные массивы (по умолчанию 200)
set print repeats 0    # не схлопывать повторы в "<repeats N times>"
```

## Шпаргалка

| хочу | команда |
|------|---------|
| весь статический массив | `p arr` |
| в hex | `p/x arr` |
| элемент | `p arr[i]` |
| срез N штук с i-го | `p arr[i]@N` |
| массив по указателю (в функции) | `p *arr@len` |
| длина статического массива | `p sizeof(arr)/sizeof(arr[0])` |
| поймать изменение элемента | `watch arr[i]` |
| поменять элемент | `set var arr[i] = 42` |
| авто-показ каждый шаг | `display arr` |
| тип переменной | `whatis arr` / `ptype arr` |
